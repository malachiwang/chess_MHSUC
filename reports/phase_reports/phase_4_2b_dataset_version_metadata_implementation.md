## 2. ELI5 / TLDR

This ticket creates `dataset_version.py`, a module that assembles all four per-stage metadata files (parser, cleaning, features, assessment) into a single unified machine-readable manifest (JSON) and a human-readable dataset card (Markdown). No data is transformed or modeled.

## 4. Metadata Standard Implemented

The unified manifest (`dataset_version_lichess_ten_zero_2024_09_25k_v1.json`) contains:

| Section | Contents |
|---------|----------|
| `provenance` | dataset_id, version_tag, source_url, source_file, source_month, time_control, raw_games_cap, git states, Python version, dependency versions, platform |
| `artifacts` | All 11 pipeline artifacts with path, role, stage, file format, size, SHA256, row/column counts |
| `pipeline_stage_outputs` | Per-stage inputs, outputs, metadata paths, key row counts |
| `pipeline_policy` | Parser rules, cleaning rules, feature rules, leakage policy, target policy, split policy |

| `dataset_summary` | Row counts, result distribution, eval coverage, caveats, readiness flags |

| `reproducibility` | Exact CLI commands for all 5 pipeline stages |
| `data_safety` | Confirmation of no staged data, no CSV, no model files |

## 13. Risks / Assumptions

**R1 — Git dirty state at manifest generation time**
The manifest was generated while 4.2B files were uncommitted (expected). The pipeline_code_git_state.commit_hash is the authoritative reference for reproducing the data artifacts. manifest_generation_git_state is recorded for transparency.

**R2 — Parser version_tag drift**
Parser metadata records `version_tag: 'v1'` while the canonical dataset version_tag is `'2024_09_25k_v1'`. This is documented in `known_metadata_inconsistencies`. File names are correct because `run_parser._make_stem()` prepends month and cap to the tag.

**R3 — assessment_json implementation_notes.test_count = 'TBD'**
The assessment JSON placeholder was not updated after the real test run. This is documented in `known_metadata_inconsistencies`. Do not treat it as an authoritative test count.

**R4 — Local-only artifacts**
All data artifacts must be regenerated on a fresh machine. The reproduction commands require Lichess network access. The dataset card documents the exact commands.
