## 1. ELI5 / TLDR

This ticket uses the full-coverage local Stockfish eval from 8.1B to answer:
once we know how good the position objectively is, do human-context facts
(player ratings, clock situation, game phase) still help predict the outcome?

Four eval-conditioned logistic models (E1, E3, E4, E5) were trained on the
broad primary_numbered view and compared with paired game-level bootstrap
deltas. Results:

- **Every E-model beats every baseline on validation log_loss.** Best:
  E5 (full human context + sf_eval) at 0.7310 vs B3's 0.8527.
- **The key comparison E3 → E4 (clock after eval + rating) excludes zero**
  (delta −0.0138, 95% CI [−0.0266, −0.0002]) — clock carries predictive
  signal beyond objective position strength and rating. The upper bound is
  very close to zero, so this is reported cautiously.
- **B3 → E5 clearly excludes zero** (delta −0.1217, CI [−0.1565, −0.0828]) —
  the best eval-conditioned model is a resolvable improvement over the
  current champion.

All claims are predictive associations on the validation split. No causal
claims. No GBMs trained. Test split untouched for selection.

## 4. 8.1B Erratum Applied

The 8.1B reports claimed `sf_depth=12 uniform`. The artifact actually has
6,178 rows at depth 12 and **27 terminal rows at depth 0**: 26 with checkmate
already on the board (`sf_eval_mate=0`) and 1 stalemate (`sf_eval_cp=0`).
Terminal positions cannot be searched — this is expected engine behavior, not
an evaluation failure. Both 8.1B reports now carry an erratum block. The data
artifact was not changed and Stockfish was not rerun.

## 5. Join Strategy

Direct in-memory join of `sf_eval_broad` onto `feature_positions_broad` by
`(game_id, selected_position_type)` — unique in both tables. The
`(game_id, ply)` key was rejected (8.2A): 83 games have a move_N and 'last'
checkpoint sharing a ply.

Verified on the real run:
- feature table filtered to `!= 'last'`: 6,205 rows
- left join: 6,205 rows, **0 orphans**
- split counts: train=4,344 / val=931 / test=930 (hard-asserted in `main()`)
- row order preserved via explicit row index (pairing requirement)
- only `sf_*` columns + keys selected from the sf artifact (no suffixes)
- `split_set` taken from the sf artifact (verified against splits JSON in 8.1B)

## 7. Modeling Protocol

- LogisticRegression (`max_iter=1000`, `lbfgs`) — same params as B2/B3.
  No GBMs.
- Fit on train (4,344 rows) only; primary comparisons on val (931 rows);
  test metrics recorded but never used for selection (WORKFLOW.md §13).
- Best-E selection (`select_best_e_model`) reads validation log_loss only.
- Preprocessing mirrors baselines: StandardScaler numeric, passthrough
  boolean (Int8), OneHotEncoder categoricals. No nullable numerics in any
  8.2B feature set.
- Game-level cluster bootstrap (1,000 replicates, seed=42) reusing
  `bootstrap_ci.py` public functions — `bootstrap_ci.py` was not modified.
- Pairing validity (identical per-game val row order vs B3) asserted at
  runtime for all four E-models before any paired delta.

## 12. Scientific Caveats

- Fixed-depth Stockfish eval is objective position context, **not ground
  truth and not a causal variable**.
- Residual rating/clock associations after conditioning on eval are
  **predictive associations, not causal effects** of those variables on
  outcomes.
- Late checkpoints are increasingly decided positions; per-checkpoint slices
  are reported for this reason. Degradation curves are **not** established.
- DRAW metrics are directional only (59/931 val rows, 6.3%). DRAW is not
  solved.
- The E3→E4 CI upper bound (−0.0002) is extremely close to zero; the clock
  finding should be re-examined at Phase 9 scale before being relied on.
- 27 terminal sf_depth=0 rows (0.4%) are mechanically decided and trivially
  favor eval-conditioned models.
- Test split untouched for selection; test metrics recorded only.
- Phase 9 (scaling) not started.
