# Scale-Up Replication — 250k Raw Games

**Ticket:** 9.1B — Scale-Up Implementation
**Dataset:** `lichess_ten_zero_2024_09_250k_v1`
**Version tag:** `2024_09_250k_v1`

---

## 1. ELI5 / TLDR

The pilot (8.2B) found a fragile but statistically resolvable signal: clock
features still help predict game outcomes after controlling for engine eval
and ratings, with a confidence interval that barely excluded zero. This
ticket scaled the dataset 10× (25k → 250k raw games) and reran the exact
same model ablation to see if the finding survives.

**It does — cleanly.** The key E3 → E4 delta came out at **−0.0138, the
same point estimate as the pilot**, with the 95% CI narrowing from
[−0.0266, −0.0002] to **[−0.0186, −0.0091]** — now comfortably excluding
zero. Two comparisons that were unresolved at pilot scale (rating-after-eval
and context-after-clock) also now exclude zero. A new per-checkpoint
diagnostic shows the clock signal concentrates in late checkpoints
(move_30/move_40), consistent with clock pressure mattering most when time
is actually low. All claims are predictive associations, not causal.

## 2. Scale Target and Superset Sampling Caveat

- Source: same Lichess archive as the pilot
  (`lichess_db_standard_rated_2024-09.pgn.zst`), deterministic
  **first-250,000-games prefix**.
- **The 250k sample is a superset of the 25k pilot prefix.** New splits were
  redrawn game-level with seed=42, so pilot val/test games may now be in v2
  train (pilot val games are ~1.4% of the new train games). Cross-version
  comparisons are dataset-level; this is a scale-robustness test, **not** a
  fully independent cross-month external-validity replication.
- A pilot-disjoint sample (skip-offset) was considered and rejected for 9.1B:
  it would add parser churn and offset-naming ambiguity (per ticket guidance).
- The consumed raw prefix was tee-cached to
  `data/raw/lichess/lichess_2024_09_first250k.pgn` (583 MB, gitignored) so
  the Stockfish FEN-reconstruction pass read from local disk.

## 4. Pipeline Commands

Existing module CLIs run in sequence (no new orchestrator):

```bash
# 1. Parse (streams archive once; tee-caches raw prefix locally)
PYTHONPATH=src python -m chess_mhsuc.run_parser \
    --url https://database.lichess.org/standard/lichess_db_standard_rated_2024-09.pgn.zst \
    --max-games 250000 \
    --source-file lichess_db_standard_rated_2024-09.pgn.zst \
    --output-dir data/interim --version-tag v1 \
    --raw-cache data/raw/lichess/lichess_2024_09_first250k.pgn

# 2. Clean
PYTHONPATH=src python -m chess_mhsuc.cleaning \
    --game-records data/interim/game_records_2024_09_250k_v1.parquet \
    --position-records data/interim/position_records_2024_09_250k_v1.parquet \
    --output-dir data/processed --version-tag 2024_09_250k_v1

# 3. Features
PYTHONPATH=src python -m chess_mhsuc.features \
    --positions-broad data/processed/ten_zero_positions_broad_2024_09_250k_v1.parquet \
    --positions-eval data/processed/ten_zero_positions_eval_2024_09_250k_v1.parquet \
    --output-dir data/processed --version-tag 2024_09_250k_v1

# 4. Splits (report dir -> gitignored scratch to protect committed 5.1B report)
PYTHONPATH=src python -m chess_mhsuc.splits \
    --dataset-id lichess_ten_zero_2024_09_250k_v1 \
    --feature-broad data/processed/feature_positions_broad_2024_09_250k_v1.parquet \
    --feature-eval data/processed/feature_positions_eval_2024_09_250k_v1.parquet \
    --feature-metadata data/processed/feature_metadata_2024_09_250k_v1.json \
    --output-dir data/processed \
    --report-output-dir data/processed/scale_up_reports \
    --version-tag 2024_09_250k_v1

# 5. Baseline references (report dir -> scratch, protects committed 5.2B report)
PYTHONPATH=src python -m chess_mhsuc.baselines \
    --dataset-id lichess_ten_zero_2024_09_250k_v1 \
    --feature-broad ... --feature-eval ... --feature-metadata ... \
    --splits data/processed/splits_2024_09_250k_v1.json \
    --modeling-plan data/processed/modeling_plan_2024_09_250k_v1.json \
    --output-dir data/processed \
    --report-output-dir data/processed/scale_up_reports \
    --version-tag 2024_09_250k_v1

# 6. Stockfish eval (dry-run -> 1000-position medium run -> resume test ->
#    full run after explicit approval; reads local cached PGN)
PYTHONPATH=src python -m chess_mhsuc.stockfish_eval \
    --dataset-id lichess_ten_zero_2024_09_250k_v1 \
    --version-tag 2024_09_250k_v1 \
    --positions data/processed/ten_zero_positions_broad_2024_09_250k_v1.parquet \
    --raw-pgn data/raw/lichess/lichess_2024_09_first250k.pgn \
    --stockfish-path /opt/homebrew/bin/stockfish --depth 12 \
    --output-parquet data/processed/sf_eval_broad_2024_09_250k_v1.parquet \
    --output-metadata data/processed/sf_eval_metadata_2024_09_250k_v1.json \
    --output-report data/processed/scale_up_reports/stockfish_eval_2024_09_250k_v1.md \
    --overwrite
# split_set joined post-hoc from splits_2024_09_250k_v1.json (8.1B convention)

# 7. Eval-conditioned modeling (see reports/eval_conditioned_modeling_2024_09_250k_v1.md §15)
```

## 8. E3 → E4 Replication Result

| | Point delta | 95% CI | Contains zero |
|---|---|---|---|
| Pilot (8.2B, 931 val rows) | −0.0138 | [−0.0266, −0.0002] | No (barely) |
| **This run (9,823 val rows)** | **−0.0138** | **[−0.0186, −0.0091]** | **No** |

**The pilot finding is CONFIRMED.** The point estimate reproduced exactly at
10× scale and the CI narrowed ~3× (as expected from √10), now comfortably
excluding zero. Clock features add predictive signal for game outcomes after
controlling for fixed-depth Stockfish eval and ratings. This is a predictive
association on the validation split — not a causal effect.

## 11. DRAW Metrics

DRAW is 603/9,823 validation rows (6.1%) — 10× the pilot's count, but all
unweighted logistic models still predict zero DRAW rows (precision/recall/f1
= 0.0 at support 603), mirroring every earlier phase. DRAW probability mass
is carried in the probabilistic metrics (log_loss/Brier), not in argmax
predictions. **DRAW is not solved**; DRAW-specific numbers remain cautious.

## 12. Terminal sf_depth=0 Caveat

288 of 65,368 positions (0.4%) are terminal — checkmate or stalemate already
on the board. The engine reports sf_depth=0 because no search is possible;
this is expected behavior, not an evaluation failure (same semantics as the
8.1B erratum). These rows are mechanically decided and trivially favor
eval-conditioned models.

## 13. Test Split Discipline

## 14. Scientific Interpretation

Fixed-depth Stockfish eval is objective position context, not ground truth
and not a causal variable. Residual rating/clock associations after
conditioning on eval are predictive associations, not causal effects of
those variables on outcomes. The confirmed E3 → E4 result supports this
claim: *on Lichess 10+0 games from 2024-09, clock features add statistically
resolvable predictive signal for game outcomes beyond fixed-depth engine
eval and player ratings, and that signal concentrates in late-game
checkpoints.* Late checkpoints are increasingly decided positions;
per-checkpoint slices are reported for this reason. DRAW metrics must be
read cautiously because DRAW is sparse. Test split was not used for model
selection.

## 15. Limitations

- Superset sample: not an independent cross-month replication; external
  validity beyond 2024-09 is not established.
- Player-level leakage remains unresolved (usernames are not stored per
  DATA_POLICY; the same player can appear across splits). This grows with
  scale and is the largest honest caveat on persistence claims.
- Depth=12 is a pragmatic engine setting, not ground truth.
- Degradation curves are not established; per-checkpoint deltas are
  diagnostics.
- DRAW is not solved.
- Phase 10 (sequence models) not started; no claims beyond this dataset.

## 16. Reproducibility

All pipeline commands in §4. Deterministic: archive prefix is immutable,
splits use seed=42, lbfgs logistic regression is deterministic, bootstrap
uses seed=42, and the modeling report was verified byte-identical across two
full CLI runs. Artifacts live under `data/` (gitignored); the modeling
report is committed at `reports/eval_conditioned_modeling_2024_09_250k_v1.md`.
